---
title: Upgrading from visx
description: Move charts installed from the registry off visx and onto the d3-based version, with a one-shot AI prompt, manual steps, and a per-chart checklist.
---

Bklit charts no longer use visx. They now call d3 directly (`d3-shape`, `d3-scale`, `d3-geo`, `d3-sankey`), with small Bklit-owned files for the parts visx used to render. Props, markup, animations, and hover behaviour are unchanged. See the [changelog entry](/changelog/2026-10-31-built-on-d3) for what changed and why.

Charts installed with `npx shadcn@latest add @bklit/<chart>` are copied into your project, so they don't update on their own. To upgrade, add them again:

- **You never edited the chart files:** re-add each chart with `--overwrite`, then remove the old packages. That's it.
- **You edited the chart files, or import visx in your own code:** re-add the charts, re-apply your edits, and update the imports and CSS listed below. The [AI prompt](#upgrade-with-an-ai-agent) does all of this for you.

## What changed

| Before (visx) | Now |
| --- | --- |
| Curves from `@visx/curve` | Same curve names from `d3-shape` |
| `LinearGradient`, `RadialGradient`, gradient presets from `@visx/gradient` | Same API from `components/charts/gradients.tsx` (registry item `@bklit/gradients`) |
| Scales from `@visx/scale` | `d3-scale` chains; scale types from `d3-scale` |
| `visx-*` class names on lines, areas, grid lines, heatmap cells, and pie, ring and radar groups | No class names. The brush, the choropleth graticule, and patterns keep theirs |
| Choropleth `TransformMatrix` from `@visx/zoom` | Local type with the same fields, exported from `components/charts/choropleth` |
| Tooltip panel snaps to its new size | Panel springs to its new size with Motion. Turn it off with `animateSize={false}` on `ChartTooltip` |
| Up to 12 `@visx/*` packages, plus `react-use-measure` in some installs | Only the d3 modules each chart uses |

Paste this prompt into Claude Code, Cursor, Codex, or another coding agent, from the root of your project. It finds your installed charts, re-adds them, keeps your edits, fixes imports and CSS, cleans up dependencies, and checks the build. Commit your work first so you can review the result as a diff.

```text

Curves come from d3-shape, scales from d3-scale, LinearGradient / RadialGradient / gradient presets from a new @bklit/gradients item (components/charts/gradients.tsx), and lines, areas, grid lines, heatmap cells and pie/ring/radar groups no longer render visx-* class names. 4. Re-add. Run one command with every chart from step 2:
<runner> shadcn@latest add @bklit/<chart> @bklit/<chart> ... --overwrite --yes
Then check git diff --stat:
- Re-apply each customisation from step 3 on top of the new files, translating visx code with the mapping in step 5. If one no longer applies cleanly, leave it out and list it in the report.
- If the CLI overwrote a file outside <components>/charts/ and removed my code (for example extra helpers in lib/utils.ts), restore my version and keep only the additions the charts need.

8. Verify. Run the project's typecheck (its typecheck script or tsc --noEmit), lint and build, and fix errors caused by the upgrade. Search again for "@visx/" and "react-use-measure" outside node_modules and lockfiles; expect no results.

9. Report: the charts re-added; each customisation re-applied (file and one line); customisations I need to review; CSS selectors changed; packages removed and added; typecheck, lint and build results. Do not commit.
```

## Upgrade by hand

### 1. Save your edits

Start from a clean git tree. If you changed any file under `components/charts/` since installing it, keep a copy of the diff so you can re-apply it:

```bash
git status
# For each file you edited:
git log --diff-filter=A --format=%H -- components/charts/line.tsx | tail -1
git diff <that-commit> HEAD -- components/charts/line.tsx > line.patch
```

To preview what re-adding would change without writing files, use `--diff`:

```bash
npx shadcn@latest add @bklit/line-chart --diff
```

### 2. Re-add your charts

Re-add every chart you have installed in one command. `--overwrite` replaces existing files and `--yes` skips the prompts:

```bash
npx shadcn@latest add @bklit/line-chart @bklit/area-chart @bklit/bar-chart --overwrite --yes
```

Use `pnpm dlx shadcn@latest`, `bunx --bun shadcn@latest`, or `npx shadcn@latest` with yarn. Each chart reinstalls the shared items it depends on (`@bklit/chart-context`, `@bklit/grid`, `@bklit/chart-tooltip`, …), and area, bar and line charts now also install `@bklit/gradients`.

Don't re-add `*-example` items or `stat-card-*` blocks. They write `app/page.tsx`, sample data and `components/charts/index.ts`, which are your files now. Update their imports by hand (step 3).

Check `git diff --stat`. The CLI also writes `lib/utils.ts` (the `cn` helper). If you keep other helpers there, restore them.

### 3. Re-apply edits and update imports

Re-apply your saved diffs, then search the project for anything still importing visx:

```bash
grep -rn "@visx/\|react-use-measure" --include="*.ts" --include="*.tsx" . --exclude-dir=node_modules
```

Rewrite each match with the [before and after](#before-and-after) snippets below.

### 4. Update CSS that targets visx classes

```bash
grep -rn "visx-" --include="*.css" --include="*.scss" --include="*.tsx" . --exclude-dir=node_modules
```

Replace rules for lines, areas, grid lines, heatmap cells, and pie, ring and radar groups. See [Class names](#class-names) for what to use instead. Leave `visx-brush-*`, `visx-geo-graticule` and `visx-pattern-*` alone.

### 5. Remove the old packages

Remove the packages that nothing imports any more. Only list the ones in your `package.json`; pnpm, yarn and bun fail on packages that aren't installed.

```bash
# npm
npm uninstall @visx/curve @visx/event @visx/geo @visx/gradient @visx/grid @visx/group @visx/heatmap @visx/responsive @visx/sankey @visx/scale @visx/shape @visx/zoom react-use-measure

# pnpm
pnpm remove @visx/curve @visx/event @visx/geo @visx/gradient @visx/grid @visx/group @visx/heatmap @visx/responsive @visx/sankey @visx/scale @visx/shape @visx/zoom react-use-measure

# yarn
yarn remove @visx/curve @visx/event @visx/geo @visx/gradient @visx/grid @visx/group @visx/heatmap @visx/responsive @visx/sankey @visx/scale @visx/shape @visx/zoom react-use-measure

# bun
bun remove @visx/curve @visx/event @visx/geo @visx/gradient @visx/grid @visx/group @visx/heatmap @visx/responsive @visx/sankey @visx/scale @visx/shape @visx/zoom react-use-measure
```

Remove `@use-gesture/react` and `@use-gesture/core` too if you added them yourself. They were only pulled in by `@visx/zoom`.

The re-add in step 2 installs the d3 modules the charts use. If TypeScript reports a missing declaration file for one of them, add its types:

```bash
npm install -D @types/d3-shape @types/d3-scale @types/d3-array
```

Add `@types/d3-geo` for the choropleth and `@types/d3-sankey` for the sankey chart.

### 6. Verify

Run your typecheck and build, then open each chart page. The charts should look and animate exactly as before.

```bash
npx tsc --noEmit
npm run build
```

## Before and after

### Curves

```tsx
// Before
import { curveMonotoneX } from "@visx/curve";

// After
import { curveMonotoneX } from "d3-shape";

<Line dataKey="revenue" curve={curveMonotoneX} />
```

### Gradients

`LinearGradient`, `RadialGradient`, and the presets (`GradientPinkBlue`, `GradientTealBlue`, …) have the same names, props and defaults.

```tsx
// Before
import { LinearGradient } from "@visx/gradient";

// After
import { LinearGradient } from "@/components/charts/gradients";

<BarChart data={data}>
  <LinearGradient id="bar-fill" from="var(--chart-1)" to="var(--chart-1)" toOpacity={0.12} />
  <Bar dataKey="revenue" fill="url(#bar-fill)" stroke="var(--chart-1)" />
</BarChart>
```

Area, bar and line charts install `@bklit/gradients` for you. For a pie, ring or gauge, add it once:

```bash
npx shadcn@latest add @bklit/gradients
```

### Scales

```tsx
// Before
import { scaleLinear } from "@visx/scale";

const y = scaleLinear({ domain: [0, max], range: [height, 0], nice: true });
type Y = ReturnType<typeof scaleLinear<number>>;

// After
import { type ScaleLinear, scaleLinear } from "d3-scale";

const y = scaleLinear().domain([0, max]).nice().range([height, 0]);
type Y = ScaleLinear<number, number>;
```

The chart context (`useChart()`) now hands you `d3-scale` scales. They have the same methods as before.

### Lines and areas in custom layers

```tsx
// Before
import { LinePath } from "@visx/shape";

<LinePath data={data} x={(d) => x(d.date)} y={(d) => y(d.value)} curve={curveNatural} stroke="var(--chart-1)" />

// After
import { curveNatural } from "d3-shape";
import { LinePath, linePathD } from "@/components/charts/line-path";

const d = linePathD(data, { x: (d) => x(d.date), y: (d) => y(d.value), curve: curveNatural });
<LinePath d={d} stroke="var(--chart-1)" />
```

`areaClosedD` replaces `AreaClosed` and closes the area at the bottom of the y range by default. You can also call `line()` and `area()` from `d3-shape` directly.

### Groups, pointer position and sizing

```tsx
// Before
import { Group } from "@visx/group";
import { localPoint } from "@visx/event";
import { ParentSize } from "@visx/responsive";

<Group left={left} top={top}>{children}</Group>

// After
import { localPoint } from "@/components/charts/local-point";
import { ParentSize } from "@/components/charts/chart-parent-size";

<g transform={`translate(${left}, ${top})`}>{children}</g>
```

`localPoint` returns `{ x, y }` measured the same way as visx. `ParentSize` takes a render function that receives `{ width, height }`. `useElementSize(ref)` replaces `useParentSize` and `react-use-measure`.

### Choropleth zoom

```tsx
// Before
import type { TransformMatrix } from "@visx/zoom";

// After
import type { TransformMatrix } from "@/components/charts/choropleth";

const initialZoom: TransformMatrix = {
  scaleX: 1, scaleY: 1, translateX: 0, translateY: 0, skewX: 0, skewY: 0,
};
```

`useChoroplethZoom().zoom` keeps the same methods (`scale`, `translate`, `reset`, `center`, `handleWheel`, …) except `handlePinch`. Pinch zoom is handled for you.

### Sankey

```tsx
// Before
import type { SankeyNode } from "@visx/sankey";

// After
import type { SankeyNode } from "d3-sankey";
```

### Class names

Lines, areas, grid lines, heatmap cells, and the pie, ring and radar groups no longer render these classes:

`visx-linepath`, `visx-area-closed`, `visx-group`, `visx-rows`, `visx-columns`, `visx-line`, `visx-heatmap-rect`, `visx-heatmap-rects`, `visx-line-radial`

Style them with props or CSS variables instead, or put a `className` on the chart and use a descendant selector. The grid keeps its `chart-grid` class.

```css
/* Before */
.visx-rows line {
  stroke-dasharray: 4 4;
}
```

Use the prop instead:

```tsx
<Grid horizontal strokeDasharray="4 4" />
```

Or scope a selector to your chart:

```tsx
<LineChart className="revenue-chart" data={data}>
  {/* … */}
</LineChart>
```

```css
.revenue-chart .chart-grid line {
  stroke-dasharray: 4 4;
}
```

These classes are still rendered, so rules that target them keep working: `visx-brush-*` and `visx-group` on the brush, `visx-geo-graticule` on the choropleth graticule, and `visx-pattern-*` on [patterns](/docs/utility/background). The bar chart's `visx-pattern.tsx` file keeps its name.

### Tooltip size

The tooltip panel now springs to its new size when its rows change. To keep the old snap:

```tsx
<ChartTooltip animateSize={false} />
```

It is already off under reduced motion and with `damping={0}`.

## Troubleshooting

### Cannot find module '@visx/…'

Something still imports visx after you removed the packages. It is usually your own code (recipes and older docs examples imported `@visx/curve` and `@visx/gradient`) or a block file. Swap the import using [Before and after](#before-and-after).

### Could not find a declaration file for module 'd3-shape'

The d3 modules don't ship their own types. visx used to bring them in. Install the `@types/d3-*` package for each module you import, for example `npm install -D @types/d3-shape @types/d3-scale`.

### Type errors on scales or the zoom instance

`useChart()` scales are now `d3-scale` types (`ScaleLinear`, `ScaleTime`, `ScaleBand`). Replace `ReturnType<typeof scaleLinear>` types from `@visx/scale` with these. For the choropleth, import `TransformMatrix` from `components/charts/choropleth` and drop any `handlePinch` calls.

### My CSS stopped applying to lines, areas, or the grid

Those rules targeted `visx-*` classes that are no longer rendered. Move them to props such as `stroke`, `strokeWidth` and `strokeDasharray`, to the `--chart-*` variables (see [Theming](/docs/theming)), or to a `className` on the chart. See [Class names](#class-names).

### The tooltip animates when its content changes

That's the new size spring. Set `animateSize={false}` on `ChartTooltip` to turn it off.

### shadcn keeps asking whether to overwrite files

Pass `--overwrite --yes`, or answer each prompt. Without `--overwrite`, existing files are skipped and keep the visx code.

### Do I need to change my chart props?

No. Props, defaults, markup and animations are unchanged. Every documented variant was compared against the visx output before release.

For a fresh install, see [Installation](/docs/installation).
