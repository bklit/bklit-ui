Skills give AI coding agents project-aware context about Bklit UI. Once installed, your agent knows how to install charts from the `@bklit` registry, import them from the files the CLI wrote, compose and theme them, style them with Bklit's design vocabulary, and migrate existing charts.

For example, you can ask your agent to:

- "Add an area chart with tooltips to my dashboard."
- "Build a KPI stat card with a revenue sparkline."
- "Give the bar chart rounded tops and a diagonal pattern that matches our theme."
- "Use a diagonal pattern background that fades out on all sides."
- "Replace our Recharts line chart with the Bklit one."
- "Migrate all our shadcn charts to Bklit."
- "Fix the crosshair color on my candlestick chart tooltip."

## Install

```bash
npx skills add bklit/bklit-ui
```

This installs all three public skills. To install just one, pass `--skill`:

```bash
npx skills add bklit/bklit-ui --skill bklit-ui
npx skills add bklit/bklit-ui --skill bklit-ui-design
npx skills add bklit/bklit-ui --skill bklit-ui-migrate
```

Your agent loads each skill automatically when a request matches it. Learn more about skills at [skills.sh](https://skills.sh/docs/).

## What bklit-ui covers

### Project context

The skill runs `shadcn info --json` to read your project's framework, Tailwind version, aliases, and installed components (agents that don't run the injection are told to run it themselves). If the `@bklit` registry isn't configured, it falls back to adding the namespace or installing by URL.

### Installation and imports

Charts install as source with the shadcn CLI:

```bash
npx shadcn@latest add @bklit/line-chart
```

Files land in `components/charts/`, so imports use your project's alias — for example `@/components/charts/line-chart`, `@/components/charts/tooltip`, and `@/components/charts/chart-context` for `chartCssVars`. After installing, the agent reads the installed source to confirm props, since you own that code.

### Composition and theming

Root chart → `Grid` → series → axes → overlays → `ChartTooltip`; `chartCssVars` for typed tokens; series colors from `--chart-1` … `--chart-5`, which `shadcn add` leaves untouched if your theme already defines them; sequential `--chart-scale-01` … `--chart-scale-05` for heatmaps and choropleths.

### Tooltips, overlays, animation, and loading

`ChartTooltip` props (`content`, `rows`, `indicatorColor`, `dotVariant`, …), legends, markers, reference areas, projection lines, range bands, backgrounds, enter-animation defaults and replay, and the `status="loading"` hand-off.

### Catalog

17 chart items — area, bar, line, live line, composed, scatter, candlestick, profit/loss line, pie, ring, radar, gauge, heatmap, funnel, sankey, sunburst, and choropleth — plus add-ons (axes, grid, tooltip, legend, markers, background, patterns, reference area, projection line, band, bar depth, stat flow) and stat-card blocks, each with install commands and links to [docs](/docs/components), the [charts gallery](/charts/area-chart), and [Studio](/studio).

## What bklit-ui-design covers

### Reading your app's design

Before styling, the skill runs a small dependency-free script, `detect-design.mjs`, that reports your Tailwind version, color format (oklch or hsl), dark-mode strategy, `--radius`, existing `--chart-*` palette, `components.json` style, and UI primitives. Charts are styled to fit what it finds, using your tokens rather than hardcoded colors.

### Design vocabulary

Plain-English requests map to exact components and props. For example:

| You say | The agent writes |
|---------|------------------|
| "Diagonal pattern background that fades out on all sides" | `<Background />` (diagonal with a four-sided fade is the default) |
| "Squircle bars" | `BarSquares` with `squareRadius={0.5}`, plus a ring tooltip |
| "Pill bars" / "square bars" | `Bar` with `lineCap="round"` / `lineCap="butt"` |
| "3D glass bars" | `BarDepthBack` → `Bar perspective` → `BarDepthFront` |
| "Hatched area" | `PatternLines` with `PatternArea` |
| "Dashed last few days" / "forecast" | `dashFromIndex` / `ProjectionLine` |
| "Target band" | `ReferenceArea` |
| "Min/max range" / "Bollinger bands" | `Band` (+ `withBollingerBands`) |
| "Line of best fit" / "trend line" | `TrendLine` |
| "Skeleton while loading" | `status="loading"` with a `pulse` or `sweep` style |

### Recipes, taste, and theming

Fifteen ready-made compositions from the [charts gallery](/charts/area-chart), opinionated taste rules (one decorative layer, subtle patterns, faded backgrounds, corner style that matches your `--radius`), and theming guidance for light and dark mode, including fixes for Tailwind v3 projects.

When you ask for something Bklit doesn't support, such as a wave or hexagon background preset, the skill says so and offers the closest composition instead of inventing props.

## What bklit-ui-migrate covers

### Finding your charts

A dependency-free script, `detect-recharts.mjs`, lists every chart that uses Recharts directly or through shadcn's `components/ui/chart.tsx` (`ChartContainer`, `ChartConfig`, `ChartTooltipContent`).

### Planning the migration

Each chart is classified as:

- **Clean**: a direct Bklit equivalent, such as line, area, bar, pie, radar, funnel, or sankey charts.
- **Needs a workaround**: for example numeric x values on a line chart, stacked areas, or a fixed y domain. The agent asks before converting these.
- **Keep on Recharts**: no Bklit equivalent yet, such as `Treemap`, `syncId`, or `ErrorBar`.

### Converting

Files are converted one at a time: data is reshaped where needed (for example, x values to dates), components and props are mapped, and `ChartConfig` colors and labels carry over to series and tooltip rows. `components/ui/chart.tsx` and the `recharts` dependency are removed only once nothing imports them, then the project is typechecked and built.

## Contributing to bklit-ui

If you cloned the [bklit-ui repository](https://github.com/bklit/bklit-ui) to contribute, contributor-only skills live in `.agents/skills/` (see `AGENTS.md`):

| Skill | Purpose |
|-------|---------|
| **bklit-studio** | Build or edit charts: prototype in `/studio`, edit `packages/studio` and `packages/ui` |
| **bklit-ship** | Ship a chart from Studio to docs, gallery, and the shadcn registry |
| **bklit-studio-chart-performance** | Audit and fix Studio chart FPS, pan/zoom jank, and Motion subscriptions |
| **pr-open** | Commit, push, and open a PR with the bklit-ui checklist |
| **unit-tests** | Add tests without over-testing |

These skills are marked `internal` in their frontmatter, so `npx skills add bklit/bklit-ui` does not install them — they are for monorepo development only.
